# Fetch is ssh-only, and gives up after a minute

`Fetch` is the only thing Diffnote does that leaves the machine, and ADR 0003 already accepted that it borrows the reviewer's own setup to do it: gix shells out to the system `ssh` binary. Reaching a remote over HTTPS instead is a different kind of dependency — there is no system command to borrow, so Diffnote would have to speak HTTP and TLS itself — and it does not pay for its build cost (below), so the `gix` build stays at `blocking-network-client` and `Fetch` works over ssh, and over a local path for the tests. What ssh being the only transport does not remove is a hang: the `ssh` binary can ask for a key passphrase or an unknown host key, and Diffnote has nowhere to type the answer — with no terminal it fails outright, with one it sits on a prompt no reviewer will ever see — so the fetch runs on its own thread with a 60-second budget, after which gix is asked to interrupt and the reviewer is told what happened.

## Consequences

- A Repo whose remote is an `https://` URL is told so in its own terms, with the one-line `git remote set-url` that fixes it. gix's own answer names cargo features, which is no help from inside a running app.
- The abandoned thread may outlive the timeout's answer — a thread blocked on a prompt cannot be killed — but it holds nothing the rest of the app needs.
- A Repo with no remote is a repo that was never cloned from anywhere, which is an ordinary state and not a failure, so `Fetch` reports there is nothing to fetch rather than showing an error.
- Which remote to fetch from is git's question to answer, not Diffnote's: gix's `find_fetch_remote` uses the checked-out branch's configured remote and falls back to the only one there is, so a Repo with several remotes behaves the way `git fetch` does in the same folder instead of assuming `origin`.
- **If an HTTP transport is ever added back, the credential helper has to be muzzled at the same time.** gix runs git's helper cascade for HTTP auth, and that cascade falls through to a terminal prompt — the same hang, now on a path the timeout only papers over. Passing `gix_prompt::Mode::Disable` to the cascade is what closes it: a helper that already holds the credential still works, a configured `askpass` still gets its turn because it can put a window on screen, and everything else fails fast. `src-tauri/Cargo.toml` carries this warning next to the feature list, which is where someone about to make that change will be standing.

## Considered Options

- **Compile an HTTP transport in** (`reqwest` + rustls): rejected — 41 more crates against 3, measured at 602 against 564, dragging in a C crypto library (`aws-lc-sys`) that needs `cmake` and a C compiler to build: around 31 seconds and 33 MB the first time, on every machine that builds Diffnote, for a code path a reviewer whose remotes are all ssh never reaches. The recovery when ssh-only is wrong is one command on one repo, a much smaller thing than the build it would buy. Worth revisiting the moment an https remote is something Diffnote should just handle.
- **`curl` with system OpenSSL instead**: rejected — lighter at 571 crates, but it trades the build cost for an OpenSSL every platform has to supply, which on Windows is its own project.
- **Ask for the password in Diffnote's own UI**: rejected — it makes a review tool the custodian of git credentials, with storage, lifetime and platform-keychain questions attached, to serve the case where the reviewer's own git setup already fails.
- **Force `ssh -o BatchMode=yes` through `core.sshCommand`**: rejected — the override outranks the reviewer's own `core.sshCommand`, breaking a setup Diffnote was supposed to borrow rather than replace. The timeout covers the same hang without touching their configuration.
- **No timeout, and let the OS or the remote end it**: rejected — that is the never-ending spinner, and the one outcome worth spending a thread to avoid.
- **A stall timeout rather than a total one** (give up only when no bytes have arrived for a while): rejected for now — it needs progress plumbed out of gix, and a total budget is the smaller thing that answers the question this issue asked. A large first fetch is where the 60 seconds will chafe.
